GenericKanban

A fully-featured WebView2-based Kanban board COM control for Clarion applications. Drop it onto any window, populate it from your data, and handle card-move events with a handful of simple method calls.

Clarion 7+ WebView2 Runtime .NET Framework 4.8 Registration-Free COM TypeScript

🚀 What it does

  • Drag-and-drop card movement between columns
  • Programmatic card move — fires the same event as drag
  • WIP limits per column with amber/red visual indicator
  • Single-click and double-click card events
  • Rich card metadata: tags, assignees, due dates, progress
  • Hierarchical right-click context menus
  • Filter panel with colour-coded groups
  • Show/hide cards independently of the filter system
  • Built-in status system (tied to colour, filter, and menu)
  • Dark mode, board titles, and full colour customisation

🔧 How it works

  • Registration-free COM — no registry entries required
  • Renders in an embedded WebView2 browser control
  • Events routed via thread-safe queue + POST()
  • Single KanbanWrapperClass object per board instance
  • Template auto-generates boilerplate and copies all dependencies

Quick Start

  1. Add the Global Extension
    In the Clarion App, open Global Properties → Extensions → Add → GenericKanban (Global). Accept defaults unless you need Multi-DLL or a custom output directory.
  2. Add the Control Template to a Window
    Open the procedure in the App, then open its Window Designer. In the Control Templates pane, find GenericKanban Control and drag it onto the window. Give the object a name when prompted (e.g. MyKanban).
  3. Populate the board in OnPageReady
    Board population code goes in the OnPageReady virtual method — found under Local Objects → Kanban Objects → YourObjectName → OnPageReady. This fires when the WebView2 page has fully loaded and is ready to receive calls. The After Kanban Init embed fires earlier (at OpenWindow, before the page loads) and should only be used for Clarion-side setup that does not call any board methods.
  4. Handle events in OnCardMoved / OnContextMenuSelected
    Override the virtual methods in a derived class, or handle them inline in the generated KanbanProcess_ procedure.
  5. Generate and build
    The template copies all DLLs, the manifest, and wwwroot to your output folder automatically. No manual file management needed.
! ── OnPageReady virtual ──────────────────────────────────────
! Add columns
MyKanban.AddColumn('todo',       'To Do',       COLOR:Blue)
MyKanban.AddColumn('inprogress', 'In Progress', COLOR:Yellow)
MyKanban.AddColumn('done',       'Done',        COLOR:Green)

! Add some cards
MyKanban.AddCard('card1', 'todo',       'Implement login',  'OAuth2 flow')
MyKanban.AddCard('card2', 'inprogress', 'Fix report bug',   'See ticket #42')
MyKanban.AddCard('card3', 'done',       'Write unit tests', '')

! Optional: title bar
MyKanban.SetBoardTitle('Project Tracker', 030050080H, 0FFFFFFH)

Template — Control Template

Add GenericKanban Control to any procedure that has a window by opening the Window Designer and dragging the template from the Control Templates pane onto the window canvas. Multiple instances on the same window are supported — each gets its own object name and event equate.

PromptDefaultDescription
Object Name Kanban1 (auto-numbered) Name of the generated KanbanWrapperClass local object. Use this name to call all API methods.

What the template generates

  • An OLE control in the window definition wired to GenericKanban.GenericKanbanControl
  • An event equate ObjectName_Event for routing board events through Clarion's event loop
  • A KanbanProcess_ObjectName procedure that dispatches events
  • The KanbanWrapperClass local object with Init, Kill, and all virtual method stubs
  • An After Kanban Init embed point — fires at OpenWindow after Init(), for Clarion-side setup only (page not yet loaded)
  • An OnPageReady virtual — fires when the WebView2 page is fully loaded; put all board population code here

Generated embed points

After Kanban Init — fires at OpenWindow after Init() and RegisterEvents(). The WebView2 page has not loaded yet. Use this only for Clarion-side setup that does not call any board methods.

OnPageReady — fires when the WebView2 page signals it is ready. This is where all board population belongs: AddColumn, AddCard, context menu setup, status options, and appearance calls.

! All board setup (AddColumn, AddCard, SetBoardTitle, etc.) goes here.

Context Menu

Right-click on any card to trigger the context menu flow. There are two usage patterns:

  • Static menu — build the menu once in OnPageReady; the same menu appears for every card.
  • Deferred (per-card) menu — override OnCardRightClick, rebuild the menu inside the handler for the specific card, then call PARENT.OnCardRightClick(pCardId) to show it. This lets you add, remove, or disable items based on the card's current state or column.

Pass '' (empty string) as pParentId for top-level items.

AddContextMenuSep(pParentId)Adds a visual separator line.

Event Handlers

Override these virtual methods in a derived class to respond to board interactions. The generated KanbanProcess_ procedure dispatches all events automatically.

OnPageReady()
Fires once when the WebView2 page has fully loaded and the board is ready to receive calls. All board population code goes here — columns, cards, appearance, context menu, and status options.
OnCardMoved(STRING pCardId, STRING pFromColumn, STRING pToColumn)
Fires when a card moves to a different column — whether by user drag-and-drop or by a programmatic MoveCard() call. pCardId is the card identifier, pFromColumn and pToColumn are column IDs.
OnSingleClick(STRING pCardId)
New. Fires when the user clicks a card with a single click (confirmed after a 300 ms window with no second click). Use this to open a card detail view or select the card. pCardId is the card that was clicked.
OnDoubleClick(STRING pCardId)
New. Fires when the user double-clicks a card (two clicks within 300 ms). Use this for a Trello-style "open card" action. pCardId is the card that was double-clicked. A double-click does not also fire OnSingleClick.
OnContextMenuSelected(STRING pCardId, STRING pActionId)
Fires when the user clicks a context menu item. pCardId is the card that was right-clicked. pActionId is the pItemId passed to AddContextMenuItem, or the radio item ID for radio groups.
OnCardRightClick(STRING pCardId)
New in v1.2. Fires when the user right-clicks a card, before the context menu is shown. Override this to rebuild the menu per-card (dynamic menus). The base implementation calls ShowContextMenu(pCardId), which displays the menu at the right-click position. Always call PARENT.OnCardRightClick(pCardId) at the end of your override so the menu is shown — the template generates this call automatically for derived methods.
OnOtherEvent(STRING pEventName)
Catch-all for any events not handled by the specific handlers above. pEventName is the raw event name string.
ℹ️

Single vs double click: the 300 ms detection window runs entirely in JavaScript. A double-click cancels the pending single-click timer, so OnSingleClick and OnDoubleClick are always mutually exclusive for the same interaction.

Example — Handling Events

The generated KanbanProcess_MyKanban procedure already calls OnCardMoved and OnContextMenuSelected. Override them in a derived class, or handle inline by overriding the generated stub:

! ── Override OnCardMoved in the generated stub ─────────────────
MyKanban.OnCardMoved  PROCEDURE(STRING pCardId, STRING pFromColumn, STRING pToColumn)
  CODE
  ! Update your data
  GET(TaskQ, CLIP(pCardId))
  IF NOT ERRORCODE()
    TaskQ.Column = CLIP(pToColumn)
    PUT(TaskQ)
  END

  ! Optionally give visual feedback
  IF pToColumn = 'done'
    MyKanban.SetCardBackgroundColor(pCardId, 027AE60H) ! green tint
    MyKanban.SetCardProgress(pCardId, 100)
  END
! ── Or handle via a derived class ──────────────────────────────
MyKanbanClass CLASS(KanbanWrapperClass)
OnCardMoved     PROCEDURE(STRING pCardId, STRING pFrom, STRING pTo), OVERRIDE
              END

MyKanbanClass.OnCardMoved PROCEDURE(STRING pCardId, STRING pFrom, STRING pTo)
  CODE
  MESSAGE('Moved ' & CLIP(pCardId) & ' from ' & CLIP(pFrom) & ' to ' & CLIP(pTo))

MyKanban.OnContextMenuSelected PROCEDURE(STRING pCardId, STRING pActionId)
  CODE
  CASE CLIP(pActionId)
  OF 'edit'
    EditCardDialog(CLIP(pCardId))
  OF 'delete'
    IF MESSAGE('Delete this card?','Confirm',ICON:Question,BUTTON:Yes+BUTTON:No) = BUTTON:Yes
      MyKanban.RemoveCard(pCardId)
    END
  OF 'mv_done'
    MyKanban.SetCardProgress(pCardId, 100)
    MyKanban.SetCardBackgroundColor(pCardId, 027AE60H)
  END

Example — Deferred (Per-Card) Context Menu

Override OnCardRightClick to rebuild the menu for each card individually before it is shown. This lets you tailor menu items based on the card's current column, status, or any other property.

! ── YourApp.inc ────────────────────────────────────────────────
ProjectKanban CLASS(KanbanWrapperClass)
OnCardRightClick        PROCEDURE(STRING pCardId), OVERRIDE
OnContextMenuSelected   PROCEDURE(STRING pCardId, STRING pActionId), OVERRIDE
                      END

! ── YourApp.clw ────────────────────────────────────────────────
ProjectKanban.OnCardRightClick PROCEDURE(STRING pCardId)
  CODE
  ! Rebuild the menu fresh for this card
  SELF.ClearContextMenu()
  SELF.AddContextMenuItem('', 'edit',   'Edit Card...')
  SELF.AddContextMenuSep('')

  ! Show 'Mark as Done' only when not already in the Done column
  IF CLIP(SELF.GetCardColumn(pCardId)) <> 'done'
    SELF.AddContextMenuItem('', 'done', 'Mark as Done')
  END

  ! Show 'Reopen' only when the card IS in Done
  IF CLIP(SELF.GetCardColumn(pCardId)) = 'done'
    SELF.AddContextMenuItem('', 'reopen', 'Reopen')
  END

  SELF.AddContextMenuSep('')
  SELF.AddContextMenuItem('', 'delete', 'Delete Card')

  ! PARENT call shows the menu at the right-click position
  PARENT.OnCardRightClick(pCardId)

ProjectKanban.OnContextMenuSelected PROCEDURE(STRING pCardId, STRING pActionId)
  CODE
  CASE CLIP(pActionId)
  OF 'edit'
    EditCardDialog(CLIP(pCardId))
  OF 'done'
    SELF.MoveCard(pCardId, 'done')
    SELF.SetCardProgress(pCardId, 100)
  OF 'reopen'
    SELF.MoveCard(pCardId, 'todo')
    SELF.SetCardProgress(pCardId, 0)
  OF 'delete'
    IF MESSAGE('Delete this card?', 'Confirm', ICON:Question, BUTTON:Yes+BUTTON:No) = BUTTON:Yes
      SELF.RemoveCard(pCardId)
    END
  END
ℹ️

PARENT call is required. The base OnCardRightClick implementation calls ShowContextMenu(pCardId) to display the menu. If you override the method without calling PARENT.OnCardRightClick(pCardId), the menu will never appear. The Clarion template generates the PARENT call automatically for derived methods.

Example — Status System

The status system ties a colour, a context menu radio button, and a filter option together for each status value. Set it up once in OnPageReady.

! ── OnPageReady ────────────────────────────────────────────────
! 1. Define status options
MyKanban.SetStatusTitle('Priority')
MyKanban.AddStatusOption('low',      'Low',      039D353H)  ! green
MyKanban.AddStatusOption('medium',   'Medium',   0F39C12H)  ! orange
MyKanban.AddStatusOption('high',     'High',     0C0392BH)  ! red
MyKanban.AddStatusOption('critical', 'Critical', 08E44ADH)  ! purple

! 2. Wire into filter panel and context menu
MyKanban.BuildFilterFromStatus()
MyKanban.BuildMenuFromStatus('root')

! 3. Set status on cards (sets bar colour + filter + radio in one call)
MyKanban.AddCard('card1', 'todo', 'Deploy hotfix', 'Production issue')
MyKanban.SetCardStatus('card1', 'critical')

MyKanban.AddCard('card2', 'todo', 'Update docs', 'Developer guide')
MyKanban.SetCardStatus('card2', 'low')

! ── OnContextMenuSelected ──────────────────────────────────────
! Radio group events fire with pActionId = the radio item ID ('low', 'medium', etc.)

Example — Multi-DLL Setup

In a multi-DLL application, the KanbanWrapperClass must be exported from exactly one DLL and consumed by all others that need it.

⚠️

Add GenericKanban (Global) only to the apps that actually need it — not every module in the solution:

  • Data DLL (the root DLL that exports classes) — add the extension and tick Export KanbanWrapper Class from this DLL. This is the owning module.
  • EXE application that runs the board — add the extension with Part of a Multi-DLL program ticked (Export off).
  • Any other DLL that contains a procedure using the control — add the extension with Part of a Multi-DLL program ticked (Export off).
  • Other EXEs or DLLs in the solution that have no Kanban procedures — do not add the extension.
! ── Data DLL (owning module) — Global Extension settings ──────
! Part of a Multi-DLL program ............. [x]
! Export KanbanWrapper Class from this DLL  [x]

! ── EXE / DLL that uses the control — Global Extension settings
! Part of a Multi-DLL program ............. [x]
! Export KanbanWrapper Class from this DLL  [ ]  (leave off!)

! Other EXEs/DLLs with no Kanban procedures — do not add the extension

Example — Column Auto-Sort

SetColumnSortMode sets the default/initial order for a column. It re-applies automatically when a card is added, moved into the column via MoveCard, or when SetCardPriority / SetCardDueDate changes a card already in the column — but the user can always drag-reorder freely afterward; the next trigger re-applies the auto-order.

! ── OnPageReady ────────────────────────────────────────────────
MyKanban.AddColumn('todo', 'To Do', 0)

MyKanban.AddCard('t1', 'todo', 'Fix login bug',       '')
MyKanban.AddCard('t2', 'todo', 'Update docs',         '')
MyKanban.AddCard('t3', 'todo', 'Refactor auth module', '')

MyKanban.SetCardPriority('t1', 1)   ! highest priority
MyKanban.SetCardPriority('t2', 3)
MyKanban.SetCardPriority('t3', 2)

MyKanban.SetColumnSortMode('todo', 'priority')
! Column order is now: t1, t3, t2 — the user can still drag any of them around

! Sort a different column by due date instead
MyKanban.SetCardDueDate('t2', '15/08/26')
MyKanban.SetColumnSortMode('testing', 'date')

! Turn auto-sort off again (order stays as-is, just no longer auto-reapplied)
MyKanban.SetColumnSortMode('todo', 'none')

! Moving a card programmatically re-sorts the destination column too
MyKanban.SetCardStatus(t1, 'done')      ! e.g. status change drives the move below
MyKanban.MoveCard('t1', 'done')         ! 'done' has SetColumnSortMode('priority') active
                                         ! → t1 is inserted at its priority-sorted position,
                                         !   not just appended at the end
⚠️

The Status system does not drive auto-sort. SetCardStatus / AddStatusOption (colour bar, context-menu radio, filter) is a separate mechanism from the numeric Priority field that SetColumnSortMode('priority') reads. If your app changes a card's priority only through the Status system (e.g. a context-menu selection), the column will not re-sort — call SetCardPriority with the matching numeric value as well.

Example — Save / Restore Board State

GetBoardState() / SetBoardState() persist dark mode, read-only, column width, font size, language, board title/colours, per-column visibility and per-column sort mode — not columns or cards, which your app re-creates as usual in OnPageReady.

! ── Saving (e.g. on CloseWindow, or a "Save Layout" button) ────
UserPrefs.KanbanLayout = MyKanban.GetBoardState()
! Persist UserPrefs to a file/table as your app normally does

! ── Restoring (e.g. in OnPageReady, after columns are re-created) ─
! Safe to call before OR after PageReady — calls queue internally either way.
IF CLIP(UserPrefs.KanbanLayout) <> ''
  MyKanban.SetBoardState(UserPrefs.KanbanLayout)
END
⚠️

The JSON returned can grow with the number of columns (visibility + sort-mode entries). The Clarion wrapper's GetBoardState return value is declared STRING(8000) — plenty for typical boards, but verify it is not truncated on boards with an unusually large number of columns.

Example — Extending the Class

Derive from KanbanWrapperClass to keep your event handling clean and type-safe, and to add domain-specific helpers.

! ── YourApp.inc ───────────────────────────────────────────────
  INCLUDE('KanbanWrapper.inc'),ONCE

ProjectKanban CLASS(KanbanWrapperClass)
OnCardMoved             PROCEDURE(STRING pCardId, STRING pFrom, STRING pTo), OVERRIDE
OnContextMenuSelected   PROCEDURE(STRING pCardId, STRING pActionId), OVERRIDE
LoadFromDB              PROCEDURE
SaveCardColumn          PROCEDURE(STRING pCardId, STRING pColumnId)
                      END

! ── YourApp.clw ───────────────────────────────────────────────
ProjectKanban.OnCardMoved PROCEDURE(STRING pCardId, STRING pFrom, STRING pTo)
  CODE
  SELF.SaveCardColumn(pCardId, pTo)

ProjectKanban.OnContextMenuSelected PROCEDURE(STRING pCardId, STRING pActionId)
  CODE
  CASE CLIP(pActionId)
  OF 'archive'
    SELF.RemoveCard(pCardId)
    ArchiveTask(CLIP(pCardId))
  ELSE
    ! status radio — handled by SetCardStatus
    SELF.SetCardStatus(pCardId, pActionId)
    SELF.SaveCardColumn(pCardId, SELF.GetCardColumn(pCardId))
  END

ProjectKanban.LoadFromDB PROCEDURE
  CODE
  LOOP UNTIL ACCESS:Tasks.Next()
    SELF.AddCard(Tasks.Id, Tasks.Column, Tasks.Title, Tasks.Description)
    SELF.SetCardStatus(Tasks.Id, Tasks.Status)
  END

ProjectKanban.SaveCardColumn PROCEDURE(STRING pCardId, STRING pColumnId)
  CODE
  Tasks.CardID = CLIP(pCardId)
  GET(Tasks, +Tasks.CardID)
  IF NOT ERRORCODE()
    Tasks.Column = CLIP(pColumnId)
    PUT(Tasks)
  END

Example — WIP Limits

WIP (Work In Progress) limits visually warn when a column is over capacity. The count badge in the column header shows count/limit and changes colour automatically as cards are added, removed, or dragged.

! ── OnPageReady ────────────────────────────────────────────────
MyKanban.AddColumn('todo',       'To Do',       0)
MyKanban.AddColumn('inprogress', 'In Progress', 0)
MyKanban.AddColumn('review',     'In Review',   0)
MyKanban.AddColumn('done',       'Done',        0)

! Set WIP limits (0 = no limit)
MyKanban.SetColumnWipLimit('todo',       10)   ! amber at 10, red above 10
MyKanban.SetColumnWipLimit('inprogress',  3)   ! tight limit for focus
MyKanban.SetColumnWipLimit('review',      2)
! 'done' has no limit

! Load cards from a queue...
LOOP a = 1 TO RECORDS(TaskQ)
  GET(TaskQ, a)
  MyKanban.AddCard(TaskQ.Id, TaskQ.Column, TaskQ.Title, TaskQ.Description)
END

! ── Check WIP limit in OnCardMoved ─────────────────────────────
MyKanban.OnCardMoved PROCEDURE(STRING pCardId, STRING pFromColumn, STRING pToColumn)
Count                   LONG
  CODE
  ! Warn if the destination column is over its WIP limit
  Count = MyKanban.GetColumnCardCount(pToColumn)
  IF Count > 3 AND CLIP(pToColumn) = 'inprogress'
    MESSAGE('WIP limit exceeded for In Progress (' & Count & ' cards). ' &|
            'Consider completing or moving a card before adding more.',  |
            'WIP Warning', ICON:Exclamation)
  END
  ! Persist to data as normal
  UpdateTaskColumn(CLIP(pCardId), CLIP(pToColumn))

Example — Single and Double Click Events

OnSingleClick fires after a 300 ms pause with no second click. OnDoubleClick fires immediately on the second click and cancels the pending single-click — so the two events are always mutually exclusive.

! ── Override in your derived class or the generated stub ───────

MyKanban.OnSingleClick PROCEDURE(STRING pCardId)
  CODE
  ! Highlight the card and show a summary panel
  MyKanban.SetCardBorderColor(pCardId, 03498DBH)   ! blue border = selected
  ShowCardSummary(CLIP(pCardId))

MyKanban.OnDoubleClick PROCEDURE(STRING pCardId)
  CODE
  ! Open the full card editor (Trello-style)
  OpenCardEditor(CLIP(pCardId))
💡

A common pattern: use OnSingleClick to select a card (highlight border, populate a side panel) and OnDoubleClick to open it for editing. Only implement the events your app actually needs — both handlers default to empty virtuals.

To implement card selection — deselect the previously selected card and select the new one:

! ── In your derived class ──────────────────────────────────────
SelectedCardId  STRING(50)

MyKanban.OnSingleClick PROCEDURE(STRING pCardId)
  CODE
  ! Clear previous selection
  IF CLIP(SelectedCardId) <> ''
    MyKanban.SetCardBorderColor(SelectedCardId, -1)   ! -1 = remove border
  END
  ! Select the new card
  SelectedCardId = pCardId
  MyKanban.SetCardBorderColor(pCardId, 03498DBH)      ! blue border

Example — Programmatic Move and Card Visibility

MoveCard moves a card between columns without user interaction and fires OnCardMoved exactly as a drag would. SetCardVisible shows or hides a card independently of the filter panel — useful for archiving or temporarily suppressing cards without losing their data.

! ── Move a card programmatically (e.g. from a button click) ───
MyKanban.MoveCard('task-001', 'done')
! OnCardMoved fires with pFromColumn = old column, pToColumn = 'done'
! Optionally style it as done:
MyKanban.SetCardBackgroundColor('task-001', 027AE60H)  ! green
MyKanban.SetCardProgress('task-001', 100)

! ── Batch-complete all In Progress cards ───────────────────────
MyKanban.OnCardMoved PROCEDURE(STRING pCardId, STRING pFromColumn, STRING pToColumn)
  CODE
  IF CLIP(pToColumn) = 'done'
    MyKanban.SetCardProgress(pCardId, 100)
    MyKanban.SetCardBackgroundColor(pCardId, 027AE60H)
    UpdateTaskAsDone(CLIP(pCardId))   ! persist to DB
  END

! ── Hide / show cards without removing them ───────────────────
! Hide all cards assigned to a user who is on leave
LOOP a = 1 TO RECORDS(TaskQ)
  GET(TaskQ, a)
  IF CLIP(TaskQ.Assignee) = 'Jane Doe'
    MyKanban.SetCardVisible(TaskQ.Id, 0)   ! 0 = hidden
  END
END

! Show them again when she returns
LOOP a = 1 TO RECORDS(TaskQ)
  GET(TaskQ, a)
  IF CLIP(TaskQ.Assignee) = 'Jane Doe'
    MyKanban.SetCardVisible(TaskQ.Id, 1)   ! 1 = visible
  END
END

! SetCardVisible and the filter panel are independent:
! A card hidden by SetCardVisible stays hidden even if the filter
! would otherwise show it. A card shown by SetCardVisible is still
! subject to filter panel rules.
